🆕 Adicionar novo site

Existem duas rotas para o novo site:Deixe o sistema reconhecer automaticamente,ouAdicione e configure manualmente. Recomenda-se usar a identificação automática pela primeira vez e, em seguida, corrigi-la manualmente após a execução.

rota A：AI reconhecimento automático

  1. Digitar painel de controle → configurar → Configuração do ambiente, preencha HELPER_API_KEY、HELPER_BASE_URL、HELPER_MODEL。
  2. Abra o site de destino em um navegador controlado por script e permaneça na página de bate-papo real. Antes de se preparar para iniciar uma solicitação, confirme se não há outros sites ou guias irrelevantes além do site de destino no navegador controlado.
  3. Iniciar este sitereal pela primeira vez API perguntar。
  4. Se o nome de domínio ainda não existir config/sites.json , o back-end rastreará automaticamente HTML e chame auxiliar AI Faça análise de página.
  5. Após a análise bem-sucedida, a predefinição mestre será gerada automaticamente e gravada no arquivo de configuração do site.

Pontos principais:O reconhecimento automático não é um ponto“Adicionar novo site”botão dispara em vez dissoA primeira solicitação real para um nome de domínio desconhecidoacionar. Em outras palavras, se você apenas abrir a página sem enviar uma solicitação, o backend não gravará automaticamente a configuração.

rota B: Adicione e configure manualmente

  1. Clique no canto inferior esquerdo Adicionar novo site。
  2. Digite o nome do domínio, por exemplo chat.example.com。
  3. Digitar“predefinição mestre”, primeiro preencha três seletores principais mínimos.
  4. Crie o fluxo de trabalho mais curto e teste-o um por um.
  5. Finalmente salve e chame-o uma vez API。

🧰 Instruções de compatibilidade de chamada de função

Esta é a nova área de funcionalidade. O projeto agora é compatível OpenAI Formato de chamada de função padrão, pode receber os dados do cliente tools / tool_choice, mas também compatível com campos antigos functions / function_call。

Como funciona:O cliente ainda segue o padrão OpenAI método para enviar uma solicitação; o backend organizará a definição da ferramenta, o histórico da ferramenta e as restrições de chamada em conteúdo de prompt que será mais fácil de entender para o modelo do lado da web; após o retorno do modelo, o back-end tentará analisar os resultados estruturados de volta tool_calls。

Os limites devem ser vistos claramente:Isso não é nativo Tool Calling. Essencialmente, ainda depende das palavras dos prompts da web e do próprio entendimento do modelo, e não é oficial API A chamada de função é executada diretamente pela camada, portanto a estabilidade geral geralmente não é tão boa quanto a interface nativa.

Quando é mais fácil ter sucesso?

  • O modelo em si tem grande capacidade de seguir instruções e está disposto a produzir estritamente de acordo com o formato.
  • Não existem muitas ferramentas e seus nomes e responsabilidades estão claramente diferenciados.
  • A estrutura dos parâmetros é relativamente simples e não há muitos objetos profundamente aninhados.
  • As palavras do prompt do sistema são relativamente limpas e não contêm muitos requisitos irrelevantes.

Quando é mais provável que falhe?

  • O modelo não é inteligente o suficiente e não pode ser compreendido de forma estável“Chamadas de ferramenta estruturadas devem ser geradas”este assunto
  • Os nomes das funções são semelhantes e existem muitos parâmetros.schema muito complicado
  • A palavra-chave é muito longa e a atenção do modelo é distraída pelo conteúdo do texto.
  • A saída do modelo é misturada com texto explicativo, resumo em linguagem natural ou formato incompleto JSON, fazendo com que o back-end não consiga analisar

A gestão de expectativas mais importante:se você encontrar“Comando errado”“Os parâmetros não correspondem”“Ficou claro que ele deveria ajustar a ferramenta, mas ele disse algo diretamente”“O prompt de back-end não pode ser analisado tool_calls”Esse tipo de fenômeno geralmente não significa que seu cliente esteja conectado incorretamente, mas que o modelo web não consegue completar de forma estável a saída desta chamada de função.

Sugestões práticas

  1. Apenas dê primeiro 1 chegar 3 Não amontoe uma dúzia de ferramentas em uma só ferramenta.
  2. Mantenha os nomes das funções tão curtos e claros quanto possível e não entrem em conflito entre si.
  3. parâmetro schema Tente ser o mais plano possível, evite objetos profundos e matrizes complexas primeiro
  4. Dar prioridade a modelos mais fortes e obedientes; quando o modelo não é forte o suficiente, não importa quantas regras você escreva, ele poderá falhar.
  5. Se você achar que a análise sempre falha, simplifique primeiro as ferramentas e os parâmetros e depois considere alterar o modelo.

🗂️ conjunto de guias

O pool de guias é o principal mecanismo de agendamento deste projeto. O script verifica automaticamente todos os arquivos abertos no navegador AI guias do site e atribua umnúmero persistente。

Princípio de funcionamento

  1. Você abre um ou mais em seu navegador AI Guias do site (por exemplo ChatGPT、Gemini espere)
  2. O script detecta e adiciona-os automaticamente ao conjunto de guias, atribuindo números (1, 2, 3...）
  3. API Quando uma solicitação chega, uma guia inativa é selecionada automaticamente para processamento.
  4. Após a conclusão do processamento, a guia é liberada de volta ao pool para aguardar a próxima solicitação

Dois métodos de roteamento

roteamentoFormato de endereçoilustrar
Rota padrão /v1/chat/completions Selecione automaticamente uma guia gratuita para lidar com a solicitação
Especifique o nome de domínio do site /url/{nome de domínio}/v1/chat/completions Combine automaticamente a guia correspondente ao nome de domínio, por exemplo /url/gemini.com/v1/chat/completions
Especifique a página da guia /tab/{número de série}/v1/chat/completions Use uma guia com um número específico e coloque-a na fila se estiver ocupada

💡 Quando usar guias específicas:

  • Quando você deseja que um cliente sempre use um determinado AI horário do site
  • Quando você configura padrões diferentes para guias diferentes (consulte "Sistema padrão" abaixo)
  • Quando você precisa garantir a continuidade da conversa

  • Veja o atual URL e contagem de solicitações

  • Alternar entre diferentes configurações padrão para guias

⚠️ Coisas a serem observadas:

  • Após fechar a aba no navegador, o número correspondente será liberado automaticamente.

  • chrome://newtab A página em branco não será adicionada ao pool e não será reconhecida até que a página seja carregada.

Lógica de detecção

Gerar julgamento final = (Tempos estáveis ​​contínuos ≥ Número de julgamentos estáveis) AND (tempo de silêncio > Limite de tempo limite silencioso)

Como funciona:

  1. O script verifica o conteúdo da página a cada segundo do "intervalo de verificação padrão"
  2. Se o conteúdo mudar, reinicie o contador
  3. Se o conteúdo não mudou, o número de estáveis +1, o tempo silencioso se acumula
  4. Quando ambas as condições forem atendidas ao mesmo tempo, determine AI Geração concluída
  5. Se o conteúdo não for detectado após o tempo de “espera inicial”, o julgamento falhará.

⚠️ importante:de Chrome 136 começar,Chrome Foram feitos ajustes de segurança na depuração remota,padrão Chrome diretório de dadosNão é mais aceito --remote-debugging-port. se você colocar BROWSER_PROFILE_DIR Escreva diretamente o padrão do sistema User Data, o navegador pode ser aberto, mas a porta de depuração não estará realmente ativa e o script não poderá assumi-la.Chrome Para obter instruções oficiais, consulte:Changes to remote debugging switches to improve security。

Prática recomendada: Faça uma cópia do diretório de usuários dedicado
  1. Feche completamente tudo Chrome janela.
  2. Crie um novo diretório dedicado, por exemplo C:\Users\seu nome de usuário\AppData\Local\UniversalWebApiProfile。
  3. do diretório original C:\Users\seu nome de usuário\AppData\Local\Google\Chrome\User Data em, pelo menos copie Local State e o subdiretório de configuração que você deseja usar (por exemplo Default、Profile 1) para este novo diretório.
  4. existir .env Aponte o script para esta cópia e execute novamente start.bat。

Significado do campo:

Q2: O que devo fazer se falhar frequentemente durante o uso?

A: Verifique de acordo com as seguintes situações:

  1. Intervenção humana no fluxo de trabalho: durante a execução do fluxo de trabalho, você clicou em outros botões na página do navegador controlada pelo script ou trocou de página. Durante a execução do script, você não pode operar o navegador controlado pelo script, você só pode assisti-lo no máximo.
  2. Recolher borda: se você reduzir manualmente as bordas da página ou recolher determinados botões, o script poderá não conseguir operar nos elementos. Portanto, o elemento recolhido deve ser totalmente expandido (o navegador pode minimizar, mas não diminuir as bordas).
  3. Status anormal do site: verifique o status do navegador controlado pelo script. Pode ter acionado a verificação homem-máquina, as informações enviadas de uma só vez podem ser muito longas e rejeitadas pelo site, ou o conteúdo enviado pode conter informações ilegais e ser interceptado.
  4. problemas de rede: Flutuação de rede ou comutação de proxy IP, fazendo com que o envio falhe. Esta situação pode causar um deadlock do script, exigindo que o script seja reiniciado ou aguarde aproximadamente 5 minuto. O desempenho é o seguinte: o background do script mostra que o envio foi bem-sucedido, mas as informações no navegador não são realmente enviadas ou falham após serem enviadas.
  5. Não mantenha páginas irrelevantes em navegadores controlados: quando o script estiver prestes a ser executado, nenhum site ou guia não relacionada além do site de destino deverá existir no navegador controlado. A página do tutorial não ocupará mais automaticamente a aba controlada do navegador, mas se você abrir manualmente a página de pesquisa, página de informações ou outras páginas da web comuns, ainda poderá interferir no script; se já estiver aberto e ocorrer uma exceção, basta reiniciar o script.
  6. Falha na configuração do site: Se os problemas acima forem eliminados, pode ser que a configuração do site tenha expirado e precise ser atualizada. você pode GitHub Levante Issue Ou adicione feedback do grupo. Se você tiver uma certa base, também poderá atualizar manualmente a configuração do seletor.
